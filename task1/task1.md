# [Сравнение компонентов RAG-решения]()

## LLM-модели

| Критерий | Локальные модели | Облачные модели |
|---|---|---|
| Качество ответов | Зависит от модели | Высокое |
| Скорость работы | Зависит от модели/железа | Высокое |
| Стоимость владения и использования | Зависит от масштаба использования | Ниже при небольших масштабах |
| Удобство и простота развёртывания | Больше гибкости, сложнее в развёртывании | Простота развёртывания |

## Эмбеддинги

| Критерий | Локальные | Облачные |
|---|---|---|
| Скорость создания индекса | Зависит от железа | Высокая |
| Качество поиска | Высокое при использовании «тяжёлой» модели | Высокое |
| Стоимость владения и использования | Зависит от масштаба — при большом потоке может быть выгоднее | Зависит от масштаба — может быть дороже локальной при большом потоке |

## Векторные базы

| Критерий | ChromaDB | FAISS |
|---|---|---|
| Скорость поиска и индексации | Быстрое | Очень быстрое |
| Сложность внедрения и поддержки | Низкая | Средняя |
| Удобство в работе | Высокое | Средняя |
| Стоимость владения | Низкая | Очень низкая |

# Возможная конфигурация сервера

Учитывая обозначенный в условии объём корпуса документов и его прирост, нет необходимости разворачивать производительный кластер серверов.

- ~18K MDX
- ~3K страниц Confluence
- ~250 PDF
- Прирост: ~5K страниц в год
- ~3K токенов на страницу + индексы + метаданные
- Итого: ~50 млн токенов

### Предлагаемая конфигурация сервера

**8 vCPU / 32 GB RAM**

# Варианты реализации решения RAG-бота для QuantumForge Software

## 1. Локальное решение

**Архитектура:**

- Локальная LLM-модель — Qwen3
- Локальный эмбеддинг — intfloat/multilingual-e5-large
- Векторная БД — ChromaDB

**Плюсы:**

- Данные не выходят за пределы корпоративной сети.
- Гибкость настройки системы.
- эмбеддинг хорошо работает с выдуманными локациями

**Минусы:**

- Требуются компетенции в развёртывании и обслуживании production AI-систем.
- Возможны сложности с масштабированием.

**Итог:** оптимальное решение в данном случае.

---

## 2. Гибридное решение

**Архитектура:**

- Облачная LLM-модель — GPT-5 mini
- Локальный эмбеддинг — MiniLM-L12-v2
- Векторная БД — FAISS

**Плюсы:**

- Минимизация отправки данных во внешнюю LLM — передаются только чанки.
- FAISS работает быстрее векторных баз.
- Нет необходимости поддерживать production AI-среду для LLM.

**Минусы:**

- FAISS не оптимальна для production-сценариев.
- Сложности с фильтрацией.
- MiniLM-L12-v2 подходит для мультиязычных документов, хотя таких требований нет.

**Итог:** решение менее оптимально за счёт необходимости использовать стороннюю LLM для внутренних документов компании.

---

## 3. Облачное решение

**Архитектура:**

- Облачная LLM-модель — GPT-5 mini
- Облачный эмбеддинг — OpenAI Embeddings
- Векторная БД — Pinecone

**Плюсы:**

- Простота развёртывания и обслуживания.
- Проверенные инструменты с низким порогом входа.

**Минусы:**

- Корпоративные данные уходят во внешнюю LLM.
- Использование Pinecone излишне для небольшого корпуса документов.

**Итог:** неоптимальное решение для текущего кейса.
